# 国赛论文冷审稿（cumcm-cold-review）

你写了一篇论文，现在要**假装没写过**，用敌对视角把它读一遍。

这个 skill 存在的理由：绝大多数队伍在 P15 花 4 小时做的是"再读一遍自己写的东西"——
而**自己写的东西自己是读不出问题的**。不是不努力，是视角不对：
作者脑子里装着"我当时为什么这么写"，评委脑子里什么都没有。

> **铁律：A 类错误不是扣分，是清零。**
> 所以审稿顺序永远是：先合规，再内容，最后润色。
> 身份信息泄露排在"数学错了"前面——数学错了掉一个奖级，泄露了直接没成绩。

---

## 第一原则：隔离必须被构造，不能被声称

**审稿人看到的输入，必须从文件系统层面确定下来，并留下证据。**

具体做法：建一个 `sop/project/review_panel/` 目录，里面**只放评委能看到的东西**：

```text
sop/project/review_panel/
├── isolation_manifest.txt     ← 证据：这个目录里到底有什么（文件列表 + 字节数 + 校验和）
├── paper/                     ← 只有 manuscript.pdf，没有 .tex、没有摘要草稿
├── appendix/                  ← 只从支撑材料解压出来的代码与数据
└── data/                      ← 题目原始数据（评委也有）
```

审稿人**只在这个目录里工作**，不读 `sop/project/`、不读 `papers/`、不读聊天记录。

### 为什么非要做这一步

因为**作者自己的摘要会"修复"评委本该掉进去的坑**。

举一个真实的机制：`sop/project/claim_ledger.md` 里写着"结论 C03 置信度：中，
仅适用于温度 15–25 ℃"。你读过它，所以你再读论文时，会**自动**把这句话补进脑子里，
于是看不出论文正文其实没写这个边界。评委没有这个文件，他会直接问：
"你这个 6.2% 的降本，在什么条件下成立？"——然后你答不上来，因为论文里真的没写。

同样的机制还有：
- 你记得 `E06b` 这个实验其实扫过 ±20%，所以看不出论文灵敏度一节只写了 ±5%
- 你记得代码里已经修了那个绝对路径，所以看不出附录里还是旧版
- 你知道那个数字最新版是 4.62，所以看不出摘要里还是 4.58

**这些坑一个都不是靠"更仔细地读"能发现的。它们只能靠"不知道"发现。**

### "我没有别的上下文"这句话不算证据

如果你让一个 AI 审稿人扮演评委，它回一句"我没有其他上下文，我只看了论文"——
**这是模型生成的描述，不是它做出的观察**。它可能刚读过 `claim_ledger.md`，
也可能没有，而你无法从这句话里区分。

能区分的是目录清单：

```text
isolation_manifest.txt
生成时间：2026-09-06 09:12:03
审稿人可见根目录：sop/project/review_panel/
# 每一行：相对路径 <TAB> 字节数 <TAB> SHA256 前 16 位
isolation_manifest.txt	0	—
paper/manuscript.pdf	1887436	3f9a2c81d0e4b7a5
appendix/code/main/run_all.py	4211	7c1e09ba22df6301
appendix/code/main/model.py	15873	ab90f2c7de551134
...
合计 27 个文件，4194304 字节
```

**这份清单是观察。** 它同时是三样东西：审稿人的输入边界、你的复现依据、
以及"我们真的做了隔离"的唯一证据。

生成方式（Windows PowerShell）：

```powershell
Get-ChildItem -Recurse -File sop/project/review_panel |
  ForEach-Object {
    $h = (Get-FileHash $_.FullName -Algorithm SHA256).Hash.Substring(0,16)
    "{0}`t{1}`t{2}" -f $_.FullName.Replace((Resolve-Path sop/project/review_panel).Path + '\',''), $_.Length, $h
  }
```

> ⚠️ **清单变了就重跑审稿。** 清单的用途就是让"我看的是哪一版"变成可查的事实。
> 如果你在审稿中途改了论文，清单就作废了——旧结论不再适用。

## 五镜头分工表（国赛语境）

**五个审稿人读同一件事，等于一份审稿读五遍。** 每个镜头必须问**不同的问题**。
镜头之间在裁定之前**互不交流**——先各自成文，再合并。

| 镜头 | 由谁扮演 | 读什么 | 找什么 | 典型致命问题 |
|---|---|---|---|---|
| ① **结论-证据支撑** | M（建模手） | 摘要、各问结论、模型评价 | 每句结论背后的证据是否真的托得住；数字是否与结果表一致 | 摘要写 $T_2=4.62$ s，结果表是 4.58 s；核心结论在正文找不到任何实验支撑 |
| ② **数学与方法正确性** | C（编程手） | 假设、符号表、模型建立、公式、求解设置 | 假设是否被用到、量纲是否闭合、约束是否完整、最优性是否被证明 | 假设"忽略摩擦"但模型里有摩擦项；漏写产能上限约束，最优解不可行 |
| ③ **对比公平性** | W（写作手） | P9 基线、对照方案、模型评价 | 基线/对照是否被给了**真正机会**（不是稻草人） | 基线用默认参数跑一次，主模型精调三天，然后宣称"提升 40%" |
| ④ **可复现性** | C 或 W（非论文主写者） | 干净目录 + 附录代码 + 支撑材料 | 真跑一遍要多久、结果偏差多少、跑不通卡在哪一行 | 硬编码 `D:\我的文档\...`；`plt.show()` 阻塞；附录代码是旧版 |
| ⑤ **意义与表述** | W（写作手） | 全文，尤其摘要与图表 | 摘要是否自足（不看正文能不能懂）、图表是否被解读、结论是否只是复述正文 | 摘要只有"建立了……模型，进行了……分析"，一个数字都没有 |
| ⑥ **合规性** | 任意一人（**不可是论文主写者**） | 全文、代码、PDF 属性、文件名、AI 声明 | 身份信息、页数、AI 声明位置、附录完整、支撑材料与论文一致 | PDF 元数据 Author 残留姓名；AI 声明放在参考文献之后 |

### 镜头可以合并，但两个底线不能破

时间不够时，⑥ 合规性**永远第一个保**（它是清零项），① 与 ⑤ 可以合并成一次通读，
③ 与 ② 可以合并（都在审模型），④ 不能与任何镜头合并——它必须**动手跑**，
而"读"和"跑"是两种不同的证据。

**两条不可破的底线：**

1. **不能审自己主写的章节。** 论文主写者不审摘要与结论（那是他写的）；
   代码主写者不审复现（他会照着自己的记忆跑，而不是照着附录跑）。
   交叉审稿的意义不在于"多一双眼睛"，而在于**多一个不知道的人**。
2. **至少一人扮演"恶意评委"**，他的任务不是挑错字，而是对每条结论问：
   **"这条结论凭什么成立？如果我反对，你拿什么说服我？"**
   判据：报告里至少有 3 条"证据充分性"类问题——纯挑错的产物。

### 为什么要跨镜头交叉

因为不同镜头**在不同位置出错**。① 号和 ⑤ 号会一起漏掉量纲错误（他们看的是叙述），
② 号和 ④ 号会一起漏掉摘要不自足（他们看的是技术细节）。
一个镜头报、四个镜头没报的问题**不代表它弱**——它可能只是恰好落在别的镜头的盲区里。
反过来，五个镜头都报的问题**也仍可能是错的**（大家一起被同一个漂亮说法骗了）。
所以裁定（元审稿）必须在五份报告都成文之后再做。

## 严重级判据

**用一句话判定：这个问题会不会让评委直接否掉这篇论文？**

| 严重级 | 判据 | 处置要求 |
|---|---|---|
| **致命** | 两种情况之一：(a) 可能导致**取消评奖资格**——身份信息泄露、附录缺源程序或跑不出论文的数、支撑材料与论文不符、AI 声明缺失或位置错误；(b) 会让**结论不成立**——核心结论无证据、约束不满足、论文数字与代码不符 | **必须修复**。状态改为「已修复」后方可进入 P16 |
| **严重** | 明显降低评分但不推翻结论：假设与模型脱节、量纲不一致、只报训练集指标、灵敏度只做单参数、图表无单位、符号前后不一致、结论无适用边界、基线是稻草人 | 修复，**或**在报告中书面说明为什么不修（三条正当理由见下） |
| **轻微** | 影响可读性但不影响结论：标点混用、图内字号偏小、措辞不统一、参考文献格式细节 | 尽量修复，可批量处理；时间不够可以「不修」 |

**判据的边界（防止两头出错）：**

- **"什么都算致命"** 会让报告失去优先级，等于没有分级。致命只留两类：
  取消资格、结论不成立。**"图 4 配色不好看"永远不是致命。**
- **"什么都算轻微"** 会让致命问题溜进 P16。凡是涉及**数字能不能被复现**、
  **身份信息有没有出现**、**AI 声明在哪**的问题，一律按致命处理。
- 拿不准时问第二个问题：**"如果评委只看到这一个问题，他会怎么处置这篇论文？"**
  直接不看 / 直接否 → 致命。扣分但不否 → 严重。只是读起来别扭 → 轻微。

## 元审稿（meta-review）

五份报告汇总后，**元审稿不是取平均，是逐条裁定。**

对每一条发现，给出三种裁定之一：

| 裁定 | 含义 | 依据 |
|---|---|---|
| **确认** | 问题真实存在，且我能在论文/代码里指到具体位置 | 位置 + 原文片段 |
| **不成立** | 报告看错了（比如把符号表里的 $E_t$ 和公式里的 $E$ 当成同一个） | 说明为什么看错 |
| **需补证据** | 问题可能真实，但审稿人没拿到判断所需的东西 | 明确列出缺什么 |

然后按**"真实评委的拒稿理由会落在哪一条上"**排序，产出优先级修复清单。
每一条要写两件事：**改什么**，以及**改这个要花多久**。

排序规则（时间不够时的取舍顺序）：

1. 致命 + 15 分钟内能改 → **立刻改**
2. 致命 + 要改 1 小时以上 → 评估"改论文表述"的降级方案（把强结论改成条件结论）
3. 严重 + 影响摘要 → 改（摘要决定评委要不要细看）
4. 严重 + 只在正文 → 排后面
5. 轻微 → 批量处理或明确「不修」

> 💡 **降级方案常常比返工更优。** 发现"最优性没证明"时，
> 把论文里的"求得全局最优解"改成"在多起点实验中取得的最优解，
> 相对松弛下界的间隙为 0.8%"，花 10 分钟；补一个全局最优性证明可能花 3 小时且做不出来。
> 但**降级必须诚实**：改表述的同时要在模型评价里写明局限，不能只是把话说软。

## 与 SOP 的接口（P15）

产物落到 `sop/project/review_report.md`，模板是 `sop/templates/review_report.template.md`。
模板的字段是固定的：**编号 / 类别 / 严重级 / 位置 / 问题描述 / 修复动作 / 责任人 / 状态**。

### 门禁 `no_fatal_open` 怎么判（务必理解，它决定你能不能进 P16）

脚本 `..\..\scripts\validate_pipeline.py` 的实现是**逐行**扫描：

```python
for line in txt.splitlines():
    if "致命" in line and re.search("未修复|待修复|open", line):
        offenders.append(line)      # 有一行就阻塞 P16
```

所以规则是：

1. **状态列只允许两个闭档词：「已修复」「不修复」（或「不修」）。**
   绝不能写"未修复""待修复""open""处理中""部分修复""改了一半"。
2. **致命行的状态只能是「已修复」。** 只要某一行同时含"致命"
   和"未修复/待修复/open"，P16 就被阻塞——哪怕那只是你在描述里提了一句。
3. ⚠️ **陷阱**：脚本是**子串匹配整行**，不区分列。所以
   「问题描述」里写"该问题此前标记为未修复"——
   如果同一行含"致命"，一样会阻塞。**描述里也别出现这些词。**
4. 「不修复」必须配理由，写在报告末的"不修理由登记"表里。

自查命令：

```powershell
python scripts\validate_pipeline.py --stage P15
```

它同时检查 `file_exists`（≥700 字节）、`md_has_table`（≥3 数据行）、
`md_has_headers`（含"问题""严重""状态"三个关键词）。所以报告里的小节标题
要保留这三个词，表格要用标准 Markdown 表格。

### 复现检查（P15 的第 4 节）

**必须有一名审稿人真的在干净目录跑一遍附录代码**，并记录：

| 记什么 | 为什么 |
|---|---|
| 干净目录路径 | 证明不是在原工作目录跑的 |
| 执行命令（原文） | 别人能照着重跑 |
| **耗时** | 评委没有无限时间；8 小时跑不完等于跑不通 |
| 是否成功、卡在哪一行 | 失败也是有价值的发现 |
| 核对数字个数与**偏差** | "全部一致"要写成"27 个数字全部一致，最大偏差 0.00%" |
| 发现的环境依赖 | 网络、字体、特定版本库、`plt.show()` |

> **不能跳过的理由**：官方规则原文写着"如果缺少必要的源程序、程序不能运行
> 或运行结果与论文不符，都可能会被取消评奖资格"。
> 这是唯一一条"跳过即可能没成绩"的检查。

失败也不要紧——记成严重问题并修；实在修不完，就在报告里**显式标注
"复现存在环境依赖"**，并把这个依赖写进附录说明。诚实标注比假装通过安全。

## 常见卡点与处置

| 症状 | 原因 | 处置 |
|---|---|---|
| 三人都说"我写的没问题" | 自己审自己 | 强制交叉，指定一人扮恶意评委，且**审稿对象不含自己主写章节** |
| 报告写了 40 条问题，不知先修哪个 | 没分级 | 按"致命 → 合规 → 证据 → 表述"排序，只修前两类 |
| 争论某条算不算致命 | 判据不清 | 用两问判定：会不会取消资格？结论还成立吗？ |
| 时间不够想跳过身份扫描 | 侥幸 | **不可跳过**。这是唯一"跳过即可能取消资格"的检查 |
| 修完又引入新问题 | 改动太大 | 只做最小改动；修完重跑 `validate_pipeline.py` |
| 元审稿变成"和稀泥" | 逐条裁定没做 | 每条必须落到"确认/不成立/需补证据"之一，不许"有一定道理" |
| 审稿意见互相矛盾 | 镜头串了 | 先各自独立成文再合并；矛盾本身就是信息，记下来 |

## 什么时候不要用这个 skill

- **审别人的投稿。** 那是另一件事：有保密约束（不得转发、不得引用、
  不得用于自己的工作、不得贴进会留存内容的服务），有利益冲突要回避，
  而且**没有"我们自己的上下文"可言**——你手里的信息并不比别的审稿人多。
  本 skill 的前提是"论文是我们自己写的"，这个前提不成立时，方法全变。
- **P14 之前的写作阶段。** 那时该做的是补实验、补验证，不是审稿。
  论文还没成稿时审稿，产出的是"写作建议"，不是"致命问题清单"。
- **语言润色、排版校对。** 那是 P14 末的批量工作，不属于红队。
- **预测能不能获奖。** 本 skill 产出的是**排练**，不是录取预测。
  它看不到真实的评委池、赛区报送名额、当年的竞争强度。
- **替你改论文。** 本 skill 只出报告；修复动作交回给章节的负责人。
  让审稿人顺手改论文，等于让一个人既当运动员又当裁判。
