# 从一份题面到一篇论文（cumcm-paper）

**输入**：一个赛题文件（PDF/DOCX）+ 它的附件目录。
**输出**：一个完整的论文包，含编译好的 PDF。

这个 skill 是整仓库的**总编排器**：它自己不做构图、不做审稿，而是按契约把
`sop/` 的阶段门禁与 `skills/` 里的专项技能串起来跑一遍，并把每一步的产物落盘。

---

## 第一件事：把期望说清楚（不要跳过）

**这个 skill 能保证的**：

- 结构完整、格式合规、能编译的论文（摘要页 / 正文 ≤30 页 / 无目录 / 附录含全部可运行源程序）
- **每个数字都能追到某次真实运行**的代码与结果文件（不是编的）
- 图表达到国赛交付质量（中文字体正确、矢量、有单位、有解读）
- 假设、符号、量纲、边界条件全部显式化，待澄清项逐条闭环
- 一个诚实的"局限与未完成项"清单

**这个 skill 不能保证的**：

- **获奖级建模洞察**。模型的创造性来自人；agent 会产出扎实的、有依据的模型，
  但"这个问题最妙的那一刀"往往需要人看出来。
- 与题目完全对齐的物理细节。agent 会从题面与数据里推参数，推不出来的会**明确标注为假设**
  并做灵敏度分析，而不是假装知道。

> 因此正确的用法是：**把它当"能干的合作者"而不是"自动获奖机"**。它产出的初稿
> 通常已完成 70–85% 的工作量，剩下的是人补洞察、核对物理、润色叙事。

## 一、契约：开工前必须先定下来的东西

在跑任何代码之前，产出 `paper_contract.md`：

```text
题目：              2026 A 题 药材的烘干问题
输入清单：          题面 PDF + 附件 1/2（数据）+ 附件 3（提交模板）
任务条款：          问题1 传热传质模型；问题2 恒温干燥阶段；问题3 烘干时长；问题4 尺寸变化
交付要求：          表1–表6 的数值 + result1–4.xlsx（保留 4 位小数）
求解路线：          每个任务 → 模型族 → 求解方式 → 产出
数据可用性：        哪些附件是输入数据、哪些是空白提交模板
关键假设后备：      推不出的参数走哪里（文献值 / 拟合 / 假设 + 灵敏度）
论文结构：          摘要 + 问题重述 + 问题分析 + 假设 + 符号 + 逐问模型与求解 + 检验 + 评价 + 附录
时间预算：          数据审计 / 建模 / 求解 / 验证 / 写作各占多少
```

**契约的三条硬规则**：

1. **空白模板不是数据**。`result*.xlsx` 这类附件往往是提交模板（列全空），
   `intake.py` 会自动标出它们；把模板当输入去建模是最常见的低级错误。
2. **每个任务必须绑定一个产出**（表 N / resultN.xlsx / 一个数值结论）。绑不上的任务说明还没读懂。
3. **推不出的参数必须显式登记**，在论文里写成假设并做灵敏度分析，不许静默取值。

## 二、流水线：10 段，每段有产物与验收

| 段 | 名称 | 产物 | 验收要点 | 谁做 |
|---|---|---|---|---|
| **S0** | 勘察 | `intake/problem_spec.md`、`intake/data_report.md`、`intake_summary.json` | 任务条款数正确、模板文件被识别 | 脚本 |
| **S1** | 契约 | `paper_contract.md` | 每任务有模型族与产出；假设后备写清 | agent |
| **S2** | 数据清洗 | `code/load_data.py`、`data/clean/*`、`figures/data_*.pdf` | 缺失/异常/量纲有处理且写明理由；六张诊断图 | agent + 脚本 |
| **S3** | 模型选型 | `model_decision.md` | 每任务 ≥2 候选、含简单基线；选择理由可写进论文 | agent |
| **S4** | 形式化 | `model_spec.md` | 符号表带单位；假设四要素；方程编号；量纲自检 | agent |
| **S5** | 实现 | `code/main/*.py` + `run_all.py` | 一条命令复现；固定随机种子；与 model_spec 逐条对应 | agent |
| **S6** | 实验 | `results/E0x_*`、`experiment_registry.md` | 每个任务有结果；每个数字可追；记录失败实验 | 脚本 + agent |
| **S7** | 验证 | `validation_report.md`、`figures/val_*.pdf` | 一致性 + 灵敏度（±10/20%）+ 稳健性 + 适用边界 | agent + 脚本 |
| **S8** | 结论冻结 | `claim_ledger.md` | 每条结论绑定 E 编号；有置信度与边界 | agent |
| **S9** | 论文 | `paper/paper.tex`、`paper/paper.pdf` | 结构齐全；数字全部来自账本；编译通过 | agent + 脚本 |
| **S10** | 自检 | `lint_report.md`、`figure_check.txt` | 合规项 0 问题；图表终检通过 | 脚本 |

**关键设计**：S0/S2/S6/S9/S10 大部分是**确定性脚本**，S1/S3/S4/S5/S7/S8/S9 需要判断力，
由 agent 按契约完成。这样既有自动化效率，又不在需要判断的地方假装自动。

## 三、怎么跑

### 全自动（推荐先跑一遍看结果）

```
1. 勘察      python scripts/intake.py --problem <题面> --data-dir <数据目录> --out <工作目录>/intake
2. 契约      读 intake 产物，写 <工作目录>/paper_contract.md
3. 建模实现  按契约写 code/，跑出 results/
4. 出图      调 skills/cumcm-figure（先立图契约）
5. 写论文    用 templates/cumcm-thesis/ 写 paper/paper.tex
6. 编译      python scripts/compile_paper.py --tex <工作目录>/paper/paper.tex
7. 自检      python scripts/lint_paper.py --work <工作目录>
```

### 用门禁跑（想看清每步是否达标）

把工作目录挂到 SOP 流水线上：各段产物与 P1/P5/P8/P11/P12/P13/P14/P16 的门禁字段同构，
所以可以直接

```
python ../../../scripts/validate_pipeline.py --project <工作目录>
```

看哪一段没过、缺什么。

## 四、每个任务的模型族路由

拿到任务条款后，先判它属于哪一族（判据见 `references/task-to-model-routing.md`）：

| 任务信号 | 模型族 | 本仓库现成弹药 |
|---|---|---|
| 出现"温度/浓度/受力/流量随时间变化"、给出初始与边界条件 | **机理 PDE/ODE** | `tutorials/algorithms/04_simulation_and_mechanism.md` |
| 给出实验测量想反推参数 | **参数辨识（最小二乘）** | `scipy.optimize.least_squares` / `curve_fit` |
| "如何安排/使…最小/最大" | **优化（LP/MILP/NLP）** | `tutorials/algorithms/01_optimization.md` |
| "给出下一期/未来若干期" | **预测（ARIMA/GM/回归）** | `tutorials/algorithms/02_prediction.md` |
| "评价/排序/建立指标体系" | **评价（TOPSIS/熵权/AHP）** | `tutorials/algorithms/03_evaluation.md` |
| "求概率/期望/风险评估" | **蒙特卡洛仿真** | `model_zoo.py` |
| 交付格式是 resultN.xlsx（网格数值） | 该任务多半要**数值解** | 网格 + `scipy.integrate` / 有限差分 |

**默认策略**：先搭**最简单能跑通**的版本拿到数（基线），再按模型族升级。
不要一上来就上最复杂的模型——第 3 天没数是最惨的失败。

## 五、论文的"精美"具体指什么

`cumcm-figure` 与 `cumcm-table-figure` 负责视觉，这里说清**论文整体**的质量线：

| 维度 | 合格线 |
|---|---|
| 摘要 | 一页内，含问题/方法/关键数值/结论；遮住正文也能读懂 |
| 结构 | 摘要 → 问题重述 → 问题分析（含框架图）→ 假设 → 符号 → 逐问模型与求解 → 检验 → 评价与推广 → 参考文献 → AI 声明 → 附录 |
| 图表 | 每张图有编号+标题+单位+解读；表格三线表；图题在下、表题在上 |
| 公式 | 全部编号；正文有引用；符号与符号表一致；单位正体 |
| 数字 | 每个数值来自 `claim_ledger.md` 的 C 编号；不许出现账本外的数 |
| 篇幅 | 正文 ≤30 页；图表合计 ≤ 22% 版面 |
| 附录 | 支撑材料文件列表 + 全部完整可运行源代码 |
| 合规 | 全文（含 PDF 元数据）无校名/姓名/学号/赛区；AI 声明在参考文献之前 |

## 七、什么时候不要用这个 skill

- 只想画一张图 / 排一张表 / 审一份论文 → 用对应的专项技能，别启动整条流水线
- 想直接抄一份现成论文 → 这既违规也拿不到分；本 skill 产出的是**你自己数据的真实结果**
- 时间只剩 6 小时 → 用 `sop/` 的 P0–P8 快速定题建模，别指望全流水线跑完
