# 论文骨架与写作纪律（paper-skeleton）

本文件只讲**从流水线产物拼出 `.tex`** 这一步。通用写作方法见
`tutorials/process/paper_writing.md`；本文件讲的是"哪一节从哪个产物来"。

---

## 一、章节 ↔ 产物映射

| 论文章节 | 素材来源 | 注意 |
|---|---|---|
| 摘要 | `claim_ledger.md` 中"写入论文=是"的结论 | **最后写**，每个数字都要能对到 C 编号 |
| 一、问题重述 | `intake/problem_spec.md` | **改写**不是复制；用不超过半页 |
| 二、问题分析 | `question_graph` / 模型推进过程 | 放总体框架图；写清各问的差异与难点 |
| 三、模型假设 | `model_spec.md` 假设节 | 四要素；`[假]` 项要在这里显式出现 |
| 四、符号说明 | `model_spec.md` 符号表 | 直接搬，含单位与来源 |
| 五、模型建立与求解 | `model_spec.md` + `results/` | 逐问一节；每节"方程→方法→结果表→结果解读" |
| 六、模型的检验 | `validation_report` / `results/E0x` | 网格无关性 + 外部验证 + 灵敏度 |
| 七、模型评价与推广 | `claim_ledger.md` 的"被放弃的结论" + 已知局限 | 优点绑定具体做法；缺点要具体 |
| AI 工具使用声明 | 队伍实际情况 | **必须在参考文献之前** |
| 参考文献 | `evidence_map.md` 来源 | 每条正文都要有引用标注 |
| 附录 | 支撑材料文件清单 + `code/` | 全部可运行源代码 |

## 二、摘要五块骨架（照这个填）

```
① 背景一句话（不超过一行，不要展开意义）
② 总体方法（我们建了什么模型，一句话）
③ 逐问结果【每一问都必须带数值与单位】
④ 检验与局限（做了什么验证，主要不足是什么）
⑤ 关键词
```

**2026A 案例的实际摘要结构**：

| 块 | 内容 | 用到的 C 编号 |
|---|---|---|
| ① | 中药材热风烘干是决定成品品质的关键工序 | — |
| ② | 建立轴对称圆柱热质耦合 PDE 模型，移动边界处理收缩 | — |
| ③-1 | 1800 s 时表面 41.31 °C、中心 37.85 °C；n=201 相对 n=801 差 0.0042% | C01, C11 |
| ③-2 | β=0.0674，模型干燥 29.6 h vs 实测 29.5 h | C06 |
| ③-3 | 烘干时长 35.30 h ≈ 1.47 天 | C07 |
| ③-4 | 半径由 2.000 cm 收缩至 1.517 cm | C10 |
| ④ | 网格与外部验证均完成；**必须如实说明**半径预测 RMSE 0.490 cm、MAPE 38.7% | C11, C12 |

> 第 ④ 块是这份摘要最值得学的地方：它**主动交代了模型的主要不足**。
> 评委看到作者清楚自己的边界，比看到一个"完美"的宣称更信任这篇论文。

## 三、数字引用纪律（本流水线的核心）

**规则**：论文里的每一个数值，都必须来自 `claim_ledger.md` 的一条 C 编号。

落地做法：
1. 写论文前，先把账本里"写入论文=是"的结论抄成一列，这就是你的**数字白名单**
2. 正文里出现白名单之外的数字 → 要么补实验进账本，要么删掉
3. 定稿前跑一遍 `lint_paper.py`，它会核对账本数值在论文中的命中率

**为什么值得这么严**：评委最容易问的一句话是"你这个 35.30 h 是怎么来的"。
有账本，你能立刻答出"E11 实验、中心点判据、β 标定后"；
没有账本，你只能回答"算出来的"。

## 四、图表落地

| 类型 | 由谁产 | LaTeX 写法 |
|---|---|---|
| 数据图 | `cumcm-figure` | `\includegraphics[width=\linewidth]{E10_p2_fields.pdf}` |
| 三线表 | `cumcm-table-figure` | `booktabs` 的 `\toprule/\midrule/\bottomrule` |
| 框架图/流程图 | `cumcm-table-figure` | TikZ，或导出 PDF 后 `\includegraphics` |

**尺寸纪律**（依据模板真实版心 16 cm）：
- 通栏图：按 16 cm 设计，写 `width=\linewidth`
- 单栏/双栏小图：**写固定 cm**（`width=8cm`），写 `\linewidth` 会放大 2 倍、字号超标
- 时空热力图：**降采样 + `rasterized=True`**。
  实测一张 12871×201 的 `pcolormesh` 不处理会让矢量 PDF 到 4171 KB（超预算 2.8 倍），
  降到 200 片并光栅化后为 46 KB

## 五、编译

```powershell
python scripts/compile_paper.py --tex paper/paper.tex --runs 3
```

要点：
- **必须 3 遍**：第 1 遍生成 aux，第 2 遍解析交叉引用，第 3 遍收敛页码
- 引擎必须是 **XeLaTeX**（模板基于 ctex，pdfLaTeX 会中文乱码）
- 本仓库的 TeX Live 在 `tools/texlive/`，不在 PATH，脚本会自动定位
- 脚本会把 `!` 开头的真错误与行号摘出来，不用在几千行日志里翻

**编译后必看**：打开 PDF，确认中文正常、公式正常、图不超出页边。

## 六、定稿前自检

```powershell
python scripts/lint_paper.py --work <工作目录>
```

五类检查与常见失败：

| 类别 | 常见失败 |
|---|---|
| A 结构 | 缺"模型检验"节；正文出现 `\tableofcontents`；AI 声明放在参考文献之后 |
| B 合规 | 源码/PDF 里出现校名；PDF 元数据残留作者 |
| C 数字追溯 | 缺 `claim_ledger.md`；论文数字与账本重合度过低 |
| D 图表 | `\includegraphics` 指向不存在的文件；有图无 `\caption` |
| E 篇幅 | PDF > 20 MB；第一页不是摘要页 |
