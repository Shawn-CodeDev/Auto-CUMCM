# 流水线细则（pipeline）

S0–S10 每一段：**输入、动作、产物、验收、卡住怎么办**。
`scripts/` 里的三个脚本承担 S0/S9/S10；其余靠 agent 按契约完成。

---

## S0 勘察（脚本）

**输入**：赛题文件（PDF/DOCX）+ 附件目录
**动作**
```powershell
python scripts/intake.py --problem <题面.pdf> --data-dir <附件目录> --out <工作目录>/intake
```
**产物**
- `intake/problem_text.txt` 题面全文
- `intake/problem_spec.md` 任务条款表（编号/首句/字数/该问要求的表/该问要求的文件）
- `intake/data_report.md` 逐文件逐列勘察（类型/缺失率/唯一值/极值）
- `intake/intake_summary.json` 机器可读摘要

**验收**
- 任务条款数与题面一致（2026A 题为 4 条）
- **空白模板被识别出来**（`result*.xlsx` 这类提交模板会被标记）

**踩坑记录（已内置处理）**
- 附录标题与正文引用的写法不同（`附录2  问题1` vs `见附录2）`），
  用"数字后跟 ≥2 个空格"锚定才能切对区块
- PDF 抽文本会**在词中间断行**（`对流换热\n系数为25`），参数正则必须容忍换行
- 附录 3/4 结构相同，**必须先切片再解析**，否则第二段会匹配到第一段的值

**卡住怎么办**：题面是扫描图（无文字层）时，intake 只能拿到空文本——
改用 OCR，或人工把题面转成 txt 后再喂给后续步骤。

## S1 契约（agent）

**输入**：S0 的全部产物
**产物**：`paper_contract.md`

必填项见 `SKILL.md` 第一节。三条硬规则：
1. **空白模板不是数据**——它是提交格式，不是输入
2. **每个任务绑定一个产出**（表 N / resultN.xlsx / 一个数值）
3. **推不出的参数显式登记**，写成假设并做灵敏度

**验收**：把契约给第三个人看，他能说出"这道题要交什么、按什么路线做"。

---

## S2 数据清洗（agent + 脚本）

**产物**：`code/load_data.py`、`data/clean/*.csv`、`figures/data_*.pdf`、`data_report.md`

**必做的质量检查**（写进报告，不是心里想）
| 检查 | 为什么 |
|---|---|
| 时间栅格与步长 | 决定数值方法的稳定性与插值方式 |
| 量程与物理合理性 | 负浓度、超量程温度是常见脏数据 |
| 单调性 | 半径/质量这类量应单调，抖动要处理 |
| 环境量 vs 物料量 | **烘房水分浓度 ≠ 药材内部浓度**，混用会算错边界条件 |

**验收**：每个清洗动作都有"方法 + 理由"，且六张诊断图（或说明为何不适用）。

---

## S3/S4 模型选型与形式化（agent）

**产物**：`model_decision.md`、`model_spec.md`

判据见 `task-to-model-routing.md`。形式化的最低要求：
- 符号表带单位与取值范围
- 每条假设四要素（陈述/依据/适用条件/后文何处使用）
- 方程编号，且**参数逐个标注来源**：`[题]` 题面给定 / `[拟]` 数据拟合 / `[假]` 本队假设

> 这个三档标注是本流水线最有用的习惯之一：写论文时"参数来源"一栏直接照抄，
> 评审无法质疑"你这个数哪来的"。

---

## S5 实现（agent）

**产物**：`code/*.py` + 一个能一键跑完的入口

**必须做到**
- 物性、扩散系数、边界条件各写成**独立函数**，便于按问题切换
- 固定随机种子（本类问题通常无随机性，但显式声明便于复现）
- 求解器容差写进代码且**说明依据**
- 脚本自身可独立运行并打印关键指标（不要只画图不报数）

**验收**：删掉结果目录，重跑入口，全部产物重建，关键数字与论文一致。

---

## S6 实验（agent + 脚本）

**产物**：`results/E0x_*`、`experiment_registry.md`

**编号约定**：`E01` 数据诊断、`E02` 网格检验、`E03–E07` 问题一、
`E08` 参数标定、`E09–E12` 问题二/三/四与验证。

**每条实验登记**：目的 / 输入 / 命令 / 输出文件 / 关键结果 / 运行时间 / 状态。
**失败也要登记**——本文的 v1→v3 模型推进过程就是从失败记录里长出来的。

**验收**：论文里每个数字都能落到某个 `E` 编号。

---

## S7 验证（agent + 脚本）

四类检验，按"便宜且致命"优先：

| 顺序 | 检验 | 本文做法 |
|---|---|---|
| 1 | 网格/时间步无关性 | n=51→801，容差 1e-6→1e-9 |
| 2 | 量纲与极限检验 | 算 Bi 数判断控制机制；与理论时间尺度对比 |
| 3 | 外部验证 | 用附件 2 的**独立观测量**（半径）比对 |
| 4 | 灵敏度 | 关键参数 ±30%，判断结论稳健性 |

**验收**：**每个结论都有数字支撑**，包括"这个结论在什么条件下不成立"。
本文如实报告了半径验证 MAPE 38.66% 的偏差，并指出成因——
**这比一个漂亮但虚假的验证有价值得多**。

---

## S8 结论冻结（agent）

**产物**：`claim_ledger.md`

每条结论：编号 / 陈述（含数值与单位） / 证据（E 编号） / 置信度 / 适用边界 / 是否写入论文。
另设**「被放弃的结论」**小节，写明原想写什么、为什么不能写。

**验收**：论文里出现的每个数值都能在账本里找到。

---

## S9 论文（agent + 脚本）

**产物**：`paper/paper.tex`、`paper/paper.pdf`

结构见 `paper-skeleton.md`。编译：
```powershell
python scripts/compile_paper.py --tex paper/paper.tex --runs 3
```
**跑 3 遍**：第 1 遍建 aux，第 2 遍解析交叉引用，第 3 遍收敛页码。
脚本会自动找 `tools/texlive` 下的引擎并摘出真正的错误行。

**验收**：编译退出码 0，无 `undefined reference`，PDF 打开中文与公式正常。

---

## S10 自检（脚本）

```powershell
python scripts/lint_paper.py --work <工作目录>
```
五类检查（结构/合规/数字追溯/图表/篇幅），任一类有硬性问题即退出码 1。

**验收**：硬性问题 0 条。
