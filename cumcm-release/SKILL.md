# 国赛提交打包（cumcm-release）

比赛的名次由前 68 小时决定，但**有没有成绩由最后 10 分钟决定**。

这个 skill 存在的理由：打包是唯一一个**"做对了没人加分、做错了直接清零"**的环节。
支撑材料与论文不符合、身份信息残留、AI 详情文件缺失——
这些与建模水平毫无关系，却足以让 68 小时归零。

> **本 skill 的产出不是"一个压缩包"，是"一个被验证过的压缩包"。**
> 二者之间的差别，就是下面第一原则的全部内容。

---

## 第一原则：验证打包后的产物，而不是产生它的工作区

**几乎每一个打包缺陷，从工作目录里看都是看不见的——因为工作目录里有那个"缺失的文件"。**

具体机制：

| 你以为 | 实际 | 为什么从工作目录看不出来 |
|---|---|---|
| "代码都在 `code/` 里" | `plot.py` 没进 allowlist | `code/` 里确实有 `plot.py`，你在里面看当然有 |
| "路径都改相对了" | 有个文件还是 `D:\我的文档\...` | 那个文件在你机器上确实能跑通 |
| "没有身份信息" | 有个 `.docx` 的属性里是校名 | 你打开 docx 看的是正文，不是文档属性 |
| "附录清单和包一致" | 包里多了一个 `__pycache__` | 打包工具自动带进去的，源目录里你也没注意 |
| "包能跑通" | 缺一个没提交的数据文件 | 那个文件在你盘上，不在包里 |

**所以流程必须是：allowlist → 复制到一个空目录 → 只扫那棵新树 → 只跑那棵新树。**

```text
   工作目录（40 个文件，含那个缺失的文件）
        │  allowlist 解析成显式列表（人工复核）
        ▼
   staging 空目录（只有 allowlisted 的文件）
        │  扫描：文件名 + 内容 + 容器内部
        │  植入已知字符串自检 → 证明扫描器在工作
        ▼
   打成一个 ZIP/RAR → 解压到**另一个**空目录 → 跑一遍
        ▼
   submission/ 里的两个文件
```

> ⚠️ **注意最后一步是"另一个"空目录。** staging 目录已经不再干净了——
> 你在里面看过、跑过、可能改过。真正的验证要在解压后的新目录里做。

## 第二原则：allowlist 而非 blocklist

**先列出"要放进去的"，不要列出"要排除的"。**

排除清单的逻辑缺陷是致命的：**排除清单是你对"自己没想到的东西"的断言。**
而恰恰是没想到的那些会泄露身份：

| 没想到的载体 | 为什么会漏 |
|---|---|
| 编辑器备份 `model.py~`、`.model.py.swp` | 不在你的"代码文件"心智模型里 |
| `__pycache__/`、`.ipynb_checkpoints/` | 工具自动生成，你从没手动建过 |
| 日志文件 `run.log` | 里面往往有绝对路径 `D:\Users\张三\...` |
| **无扩展名文件** | 文本扫描按扩展名跳过，于是**永远扫不到它** |
| Excel/Word 的**文档属性** | 内容干净，属性里有作者名 |
| 压缩包内的**目录名** | 文件夹叫 `张三的文件夹`，文件全叫 `a.py` |
| `desktop.ini`、`.DS_Store` | 系统文件，不显示在常规视图里 |

**allowlist 的做法**（写到 `submission/allowlist.txt`，每行一个路径或 glob）：

```text
# 支撑材料 allowlist —— 只列要放进去的东西
code/main/**/*.py
code/baseline/**/*.py
configs/*.yaml
data/clean/*.csv
results/**/*.csv
results/figures/*.png
requirements.txt
文件列表.txt
```

解析出的**显式文件列表**（glob 展开后的具体文件清单）才是产物，生成它的命令不是。
**必须人工逐行复核这张列表**——包内容由它决定，不由任何排除规则决定。

用 `scripts/stage_and_scan.py --allowlist` 解析并打印清单（含字节数与 SHA256）：

```powershell
python skills\cumcm-release\scripts\stage_and_scan.py --allowlist submission\allowlist.txt
```

> 💡 最省事的做法是**从第一天就用中性命名**建目录与文件：
> `code/`、`data/`、`results/`，变量名与注释里不含个人信息。
> 这样最后一天不需要"清理"，只需要"确认"。

## 第三原则：扫 staged tree，扫内容也扫名字，扫容器内部

三个"扫"必须同时做到，缺一个都会漏。

### 3.1 扫 staged tree（不是源树）

```powershell
python skills\cumcm-release\scripts\stage_and_scan.py `
  --allowlist submission\allowlist.txt --base . `
  --stage --stage-dir _stage --scan --report submission\scan_report.txt
```

`--stage` 会把 allowlisted 文件复制到空的 `_stage/`，`--scan` 只扫那棵树。
报告里会列出**逐字节扫描的完整清单**——这份清单本身就是"我确实扫了这些"的证据。

### 3.2 扫内容，也扫文件名

- **内容**：所有文本文件（含**无扩展名文件**——它们按文本读，不按扩展名跳过）
- **文件名**：相对路径的每一段都扫。目录名同样泄露。
- **中文编码**：UTF-8 / GB18030 / UTF-16 都会尝试；**UTF-8 BOM 会被剥掉**
  （留着会让 `^` 行首锚定的模式在第一行静默失配）

### 3.3 扫容器格式内部

`.docx` / `.xlsx` / `.pptx` / `.ipynb` / `.zip` 都是**容器**，正文文本藏在里面：

| 格式 | 内部结构 | 关键点 |
|---|---|---|
| `.docx` | `word/document.xml` | **Word 会把一句话切成多个 `<w:t>` run**，必须把片段拼回来再扫，否则"XX大学"被切成"XX"+"大学"就漏报 |
| `.docx` 属性 | `docProps/core.xml` 的 `dc:creator` | Word 文件属性里的作者名，正文里看不见 |
| `.xlsx` | `xl/worksheets/sheet*.xml` + sheet 名 | sheet 名也会带学校名 |
| `.ipynb` | JSON 的 `cells[].outputs` | **输出单元格**是最常被忽略的泄露点（打印出的绝对路径） |
| `.zip` | 嵌套成员 | 递归展开（脚本支持到 3 层），扫成员名也扫成员内容 |

`stage_and_scan.py` 直接读 ZIP 内部 XML，不需要装 python-docx / openpyxl。

### 3.4 植入已知字符串：区分"零发现"与"扫描器没运行"

**这两件事输出完全一样。**

```powershell
python skills\cumcm-release\scripts\stage_and_scan.py --selftest
```

自检会在**真实格式**里植入已知串（不是放在好扫的纯文本里——那只能证明扫描器会读纯文本）：

| 植入内容 | 放在哪 | 期望抓到的模式 |
|---|---|---|
| `南京某某大学`（被切成两个 `<w:t>` run） | `.docx` 正文 XML | 中文校名 |
| `2026123456` | `.xlsx` 单元格 | 学号 |
| `/home/zhangsan/project` | `.ipynb` 输出单元格 | POSIX 家目录路径 |
| `C:\Users\zhangsan\Desktop` | **无扩展名文件** | Windows 用户名路径 |
| `江苏赛区` | 纯文本 | 赛区名 |
| `zhangsan@nju.edu.cn` | `requirements.txt` | 邮箱 |

同时放**干净对照**（查误报）和**白名单对照**（规则原文里的"XX大学""赛区信息"不应误报），
并检查 `model.py~` 与 `__pycache__` 被识别为垃圾项。
自检通过才说明"0 命中"是真的 0 命中。

> ⚠️ 自检**失败就等于本次扫描结果不可信**，不能据此提交。
> 这不是形式主义：本 skill 的开发过程中，自检就抓出了两个真实漏报
> （docx 的 XML 编码写坏、白名单把"大学"整个吞掉）。

## 国赛提交物规范（只按官方原文，勿信"学长经验"）

依据《全国大学生数学建模竞赛论文格式规范（2026 年修订稿）》与
《全国大学生数学建模竞赛人工智能工具使用规定（2026 年试行）》。

### 参赛论文（电子版）

| 要求 | 原文要点 |
|---|---|
| **单一文件** | 必须是**一个单独的文件**，格式为 PDF 或 Word 之一（**建议使用 PDF**） |
| **≤20 MB** | 文件大小不超过 20 MB；**参赛论文电子版文件不要压缩** |
| **第一页必须是摘要专用页** | 承诺书与编号专用页**不要**放在电子版论文中 |
| 与纸质版一致 | 电子版内容必须与纸质版内容及格式（**包括附录**）完全一致 |
| 摘要页 | 含标题与关键词，原则上不能超过一页；页码从此页开始，页脚中部，阿拉伯数字从"1"连续编号 |
| 正文 | 从第四页开始，**不要目录**，**不超过 30 页** |
| 附录 | 内容应包括**支撑材料的文件列表**、建模所用到的**全部完整、可运行的源程序代码**（含 EXCEL、SPSS 等软件的交互命令）等 |
| 无身份信息 | 摘要专用页、正文和附录中**任何地方**都不能有显示参赛者身份和所在学校及赛区的信息 |
| 参考文献 | 所有引用他人或公开资料的成果必须按科技论文规范列出，并在正文引用处标注 |

### 支撑材料

| 要求 | 原文要点 |
|---|---|
| **单个压缩包** | 将所有支撑材料文件使用 **WinRAR** 压缩在**一个**文件中（后缀为 **RAR 或 ZIP**） |
| **≤20 MB** | 大小不超过 20 MB |
| 内容 | 至少应包含建模所用到的**所有可运行源程序**、自主查阅使用的数据资料（**赛题中提供的原始数据除外**）、较大篇幅中间结果的图表等 |
| 文件列表 | 支撑材料的文件列表应放入**论文附录** |
| 不含承诺书与编号页 | 承诺书和编号专用页**不要**放在支撑材料中 |
| 无身份信息 | 所有文件中不能有显示参赛者身份和所在学校及赛区的信息 |
| 与论文相符 | **如果支撑材料文件与论文内容不相符，该论文可能会被取消评奖资格** |
| 无支撑材料时 | 可以不提供，并在论文附录中注明"本论文没有支撑材料" |

### AI 相关（2026 年 9 月 1 日起试行）

| 要求 | 原文要点 |
|---|---|
| 声明位置 | 应在论文**参考文献之前**设置"AI 工具使用声明" |
| 声明措辞 | 二者择一：未使用——"本参赛队在竞赛过程中未使用任何AI工具。"；已使用——"本参赛队在竞赛过程中使用了AI工具，主要用于【简要用途，如语言润色、代码调试等】，详细使用情况见支撑材料。" |
| 详情文件 | 使用 AI 的，应在支撑材料中包含 **AI工具使用详情.pdf**（**文件名必须完全一致**），内容包括四项：①所用 AI 工具名称、版本或型号；②具体使用目的和环节；③主要提示方式与使用过程说明（可附典型交互示例）；④对 AI 输出的采纳、人工修改和核验的主要情况（**语言润色除外**） |
| 违规后果 | **故意隐瞒 AI 使用情况、作出虚假声明，或者将未经必要人工审查与核实的 AI 生成内容直接作为核心建模与分析成果提交的，取消其评奖资格** |

## 与 SOP 的接口（P16）

### 门禁怎么判（`scripts/validate_pipeline.py --stage P16`）

| 检查类型 | 判据（读源码得出的实际行为） | 你要做什么 |
|---|---|---|
| `paper_size_limit` | glob `submission/*.pdf`，任一文件 >20 MB 即阻塞 | 论文 PDF 放 `submission/` 下，压到 ≤20 MB |
| `support_archive_limit` | glob `submission/*.zip`，任一 >20 MB 即阻塞 | 支撑材料存成 `.zip`（`.rar` 不在 glob 内，需另行人工确认） |
| `ai_detail_if_used` | 读 `project_state.json` 的 `ai_policy.declared`；值为 `used/true/yes/是/使用/used_ai` 之一时，要求存在**恰好** `submission/AI工具使用详情.pdf` | 用了 AI 就必须把该文件**按此文件名**放在 `submission/` 下 |
| `no_identity_in_submission` | 只检查 `submission/*` 的**文件名**是否含校名/学院/学号/赛区模式（**不读内容**） | 文件名用中性命名；**内容扫描要另外自己做**（见第三原则） |
| `checklist_all_checked` | 统计 `sop/project/submission_checklist.md` 里的 `- [ ]` / `- [x]`，**有任何一个未勾选就阻塞** | 每一项做完才勾；不适用的也要勾上并写"不适用+理由" |
| `file_exists` | `sop/project/submission_checklist.md` ≥500 字节 | 用模板填完整，别只写标题 |

**两个容易踩的坑：**
1. `no_identity_in_submission` **只看文件名**。文件名干净不代表包内容干净——
   内容扫描必须用本 skill 的 `stage_and_scan.py --scan` 另做一遍。
2. `checklist_all_checked` **不区分"该勾"和"不该勾"**。清单里写了一条
   "确认论文质量足够好"这种无法验证的条目，你永远勾不上，P16 永远阻塞。
   所以清单里每一条都必须是**提交前确实能做完并确认的动作**。

### `submission_checklist.md` 怎么填

复制 `sop/templates/submission_checklist.template.md` 到 `sop/project/submission_checklist.md`，
并按实际数值替换【】占位。填写要点：

| 节 | 要点 |
|---|---|
| 0 提交基本信息 | 截止时间以官网/赛区通知为准；**自设提交时刻必须早于 hard_stop（71 h）**；论文/支撑材料文件名中性 |
| 1 参赛论文文件 | 每一条都要**打开文件确认**，不要凭记忆勾；实测大小、页数写进括号 |
| 2 支撑材料 | 逐条对齐包内实际内容；"已解压到另一目录跑通"必须是**真跑过** |
| 3 AI 相关 | 未使用 AI 也要勾（按"已确认不适用"处理，并写明声明已写"未使用任何 AI 工具"） |
| 4 提交记录 | 提交后**立刻**填，含回执截图文件名与第二复核人 |
| 5 赛后归档 | 24 h 内完成，把 `sop/project/` 全部产物一起归档 |
| 6 最后 10 分钟确认 | 打印出来三人各一份，逐条口头确认 |

## 时间盒：T+68h → T+71h

| 时刻 | 动作 | 谁 | 关键产出 |
|---|---|---|---|
| **T+68h** | P15 门禁通过（致命问题清零） | ALL | `review_report.md` 无未闭合致命项 |
| T+68h–T+68.5h | **"取消资格"四项检查**：身份信息 / 论文格式 / 电子版形态 / AI 合规 | ALL | 四项结论写进 `submission_checklist.md` 第 1–3 节 |
| T+68.5h–T+69h | 写 allowlist → 复核清单 → stage → scan → 打包 | W+C | `scan_report.txt`（0 命中 + 自检通过） |
| T+69h–T+69.5h | 解压到**另一个**空目录跑通全部问题，比对论文数字 | C | 复现记录（耗时 + 偏差） |
| T+69.5h–T+70h | 生成《AI工具使用详情.pdf》（若用 AI）；核对附录文件列表与包内容逐项一致 | W | 详情 PDF + 一致的清单 |
| T+70h–T+70.5h | 逐项勾选 `submission_checklist.md`；跑 `--stage P16` 门禁 | ALL | 门禁全绿 |
| **T+70.5h** | **提交**（论文 + 支撑材料分别上传），截图回执 | W | 回执截图 |
| T+70.5h–T+71h | **重新下载验证**：打开 PDF 与压缩包，确认页数/内容/可解压 | 第二人 | 验证记录 |
| T+71h | **硬截止（自留缓冲终点）** | — | 已归档 |
| T+72h | 官方截止 | — | — |

**三条硬规则：**

1. **留 1 小时缓冲。** 提交系统会拥堵，官方截止前 30 分钟是高峰期，上传可能失败或超时。
   T+70.5h 提交，留 1.5 小时应对意外（网络、格式、需要重新打包）。
2. **提交后必须重新下载验证。** 上传损坏是真实存在的失败模式——
   重新下载后能打开、页数正确、压缩包能解压，才算提交成功。
3. **三人互相确认看到"提交成功"。** 不只由一人操作，不只由一人确认。

> 💡 超时的收缩顺序：先砍"赛后归档"→ 再砍"美化的排版细节"→
> **绝不能砍**身份扫描、AI 详情、重新下载验证。前三项是清零项。

## 常见卡点与处置

| 症状 | 原因 | 处置 |
|---|---|---|
| 论文 PDF 超 20 MB | 图片分辨率过高 | 重导图片为 150–300 DPI；删掉非必要截图；论文 PDF **不要**再压缩打包 |
| 支撑材料超 20 MB | 打包了原始数据或中间大文件 | **赛题提供的原始数据不用放**；只放清洗后数据与关键结果；删掉 `__pycache__` |
| 压缩包内含绝对路径目录 | 压缩工具默认保留路径 | 用"压缩到根目录"选项；解压检查目录结构，重新打包 |
| 附录清单与包内容不一致 | 打包后又改了内容 | **以包内容为准**重新生成清单并更新附录，**重新编译论文**（这是致命项） |
| 文件名里有学号残留 | 早期命名没注意 | 重命名为中性名；注意 `no_identity_in_submission` 会拦 |
| 用了 AI 但门禁说缺详情文件 | 文件名不一致或放错目录 | 文件名必须**恰好**是 `AI工具使用详情.pdf`，且放在 `submission/` 下 |
| 门禁说"清单还有 N 项未勾选" | 有无法验证或确实没做的条目 | 做完再勾；不适用的条目改成"已确认不适用 + 理由"再勾 |
| 提交后打不开下载的文件 | 上传损坏 | 立即重新上传；这就是要留 1 小时缓冲的原因 |
| 字数/页数超限 | 正文 >30 页 | 优先删重复图表与客套段落，**不要**压页边距（规范要求 ≥2.5 cm） |

## 什么时候不要用这个 skill

- **论文内容与建模质量的问题。** 那是 `cumcm-cold-review` 的事。
  本 skill 只保证"包是对的、合规的、能跑通的"，不保证"结论是对的"。
- **排版与配图。** 页边距、字体、图题位置 → `cumcm-figure` / `cumcm-table-figure`。
- **提交系统的账号、网络、验证码故障。** 那不在本 skill 范围内，
  但"留 1 小时缓冲 + 换浏览器重试 + 重新下载验证"是通用的应对。
- **已经提交之后的补救。** 本 skill 的流程是提交前的；
  提交后发现缺陷，只能走赛区/组委会的沟通渠道，不是重新打包能解决的。
- **把敏感材料交给会留存内容的第三方服务。** 参赛包在上传前属于未公开作品；
  用外部服务扫描前先确认它的数据政策。
