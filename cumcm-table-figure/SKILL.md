# 国赛论文的表格与示意图（cumcm-table-figure）

把**证据**摆成**可核对的清单**，把**论证**画成**看得懂的路径**。

这个 skill 存在的理由：表格与示意图的失分几乎从来不是"不好看"，而是三件事——
**表没有结论**（一屏数字，评委不知道该看哪一行）、**图没有方向**（方框乱摆，箭头乱指，
评委不知道从哪读起）、**数字对不上**（表里 4.62，摘要写 4.6，正文写 4.58）。

本 skill 只做"不是用数据点画出来的图"和"所有表格"。折线/散点/热力/龙卷风/收敛曲线等
**数据图**归 `cumcm-figure`；两者共用同一套配色与尺寸口径，见下文"与 cumcm-figure 的接口"。

## 第一动作：先立契约，再排版

**在生成或修改任何 LaTeX 表格/示意图代码之前**，先产出下面这份契约（写在
`sop/project/table_contract.md`，或直接回复里）。跳过这一步直接排表，是本 skill 最严重的误用。

```text
编号：              表 3 / 图 2
核心结论：          一句话，必须带动词和方向（"混合整数模型把日成本降低 6.2%"）
                   ✗ 不合格："各方案结果对比"（没有动词、没有方向、没有结论）
模式：              table / schematic
  table 子型：      变量说明表 / 结果对比表 / 灵敏度表 / 参数表 / 算法对比表 / 方案明细表
  schematic 子型：  模型框架图 / 求解流程图 / 算法框图 / 机理示意图
列（或模块）必要性：逐列写"删掉它，结论会变吗？"；不会 → 删掉这一列/这个方框
行（或路径）顺序：  排序依据（目标值降序？问题顺序？参数敏感性降序？）
证据层级：          主证据（hero）/ 对照与基线 / 稳健性
数据来源：          E0x 实验编号 + 结果文件路径（必须能追到 P11 experiment_registry.md）
支撑结论编号：      C0x（来自 P13 claim_ledger.md；写不出来说明这张表不该存在）
数字规格：          有效位数 / 单位出处 / 空值符号 / 最优值是否加粗 / 显著性标记
表注或图注草稿：    caption 要能让读者不看正文就懂；注里写清单位、来源、缩写、显著性定义
正文解读：          表/图后 2～4 句（描述型 → 机制型 → 决策型）
审稿风险：          恶意评委最可能攻击哪一列、哪个数、哪条连线？
版面预算：          是否超 \linewidth？会影响分页吗？表内字号取几号？
```

### 契约的三条硬规则

1. **每张表/图必须绑定一个 C 编号（结论编号）**。
   绑不上结论的表 = 数据搬运 = 占用 30 页额度 = 删掉或并入附录。
   国赛正文硬上限是 30 页（从第 4 页起算），**一张表占地就是文字让位**。

2. **表格按"列的必要性"删，示意图按"模块的必要性"删**。
   表的自检问法："删掉这一列，任何一行的结论会变吗？"（不会 → 删列）。
   图的自检问法："遮住这个方框，流程还讲得通吗？"（还通 → 删框）。

3. **一张表/图只有一个核心结论**。
   想表达两个结论 → 拆成两张，或者明确分成主表与附表（不等大、不同字号）。

## 两种模式

| 模式 | 交付物 | 评委在这上面读什么 | 通过的判断标准 |
|---|---|---|---|
| `table` | 三线表（booktabs） | **数字**：可比较、可复算、可追溯 | 每一列都通过"删掉它结论会变吗"；每个数字都能追到 E0x/C0x |
| `schematic` | 框架图 / 流程图 / 框图 / 机理图 | **结构**：谁依赖谁、先后顺序、因果 | 遮住任一模块流程就断；阅读方向唯一；连线有语义 |

**不要用示意图承载数值结论**（"图 4 显示方案 A 更优"——那是数据图的活），
**也不要用表格承载流程**（把算法步骤写成表格，读者被迫在格子里做拓扑推理）。

| **电子版论文** | 单一 PDF/Word，**≤20 MB**，第一页为摘要页 | 示意图优先矢量 TikZ/PDF，别用 600 dpi 大位图撑体积 |
| **支撑材料** | 单个 RAR/ZIP，**≤20 MB** | 表格中间产物（CSV/脚本）打包前清掉无关大文件 |

### 二、论文排版惯例类（本仓库 `tutorials/process/paper_writing.md` §7 的口径）

| 维度 | 要求 | 说明 |
|---|---|---|
| **表题位置** | 表题在表**上方**（图题在图**下方**） | 模板已设 `\captionsetup[table]{position=top}`，把 `\caption` 写在 `tabular` 之前即可 |
| **三线表** | 只留顶线、表头线、底线；**禁用竖线** | 用 `booktabs` 的 `\toprule/\midrule/\bottomrule`；不要 `\hline`、不要 `|` |
| **表内字号** | 比正文小一号；正文 12pt → 表内 `\small`（约 10.5pt），大表才用 `\footnotesize` | 一律不要 `\resizebox` 缩字（见 `references/three-line-table.md`） |
| **单位** | 写在**表头**，格式"量名 $符号$ (单位)"；无量纲写"—" | 不要每格写单位；不要只在表注里写单位 |
| **超宽表** | 四种方案按顺序试：缩列 → 转置 → 拆表 → 横向 `sidewaystable` | 禁止用 `\resizebox{\linewidth}{!}` 把 12pt 压成 6pt |
| **跨页表** | 用 `longtable`，且**每页重复表头**、末页保留底线 | 正文 30 页里尽量不出现跨页表；能拆就拆 |
| **解读** | 每张表/图后必须有 2～4 句解读文字 | 写"由表 3 可见……"是图题，不是解读；要写结论与决策含义 |
| **引用** | 正文**在表之前**引用（"结果见表 3"），编号用 `\ref`/`\cref` | 禁止手写编号，否则插表后全篇错位 |
| **配色** | 复用 `../cumcm-figure/scripts/cumcm_style.py` 的 `PALETTE`（中性/信号/强调三家族） | 灰度打印仍要可区分；不要靠颜色单独承载语义 |
| **图内字号** | 示意图内文字不小于正文的 **80%**（正文 12pt → 图内 ≥ 9.6pt，用 `\small`/`\normalsize`） | 缩放到最终尺寸后仍能读；不要 `\scalebox{0.6}` |
| **算法伪代码** | 需额外 `\usepackage{algorithm,algpseudocode}` 并中文化输入输出 | 模板**未预装**这三个宏包，必须自己在导言区加 |

> ⚠️ **最常见的两个低级失分**：① 表格用了竖线或彩色网格（一眼看出是 Word 默认样式）；
> ② 示意图里中文变成方框/乱码（TikZ 图里写了中文却没走 ctex）。

## 表格设计规则

1. **列的必要性检验**：每一列都要能回答"删掉它，哪一行的结论会变？"。
   "备注"列、"序号"列、与正文完全重复的"公式"列，通常第一个被删。
2. **数字对齐**：同一列小数点对齐。做法二选一——
   定长小数 + 右对齐（`r`，最稳）或 `siunitx` 的 `S` 列（能处理 `±`、范围、千分位）。
3. **有效位数一致**：同一列统一位数；结果值 3～4 位有效数字；
   $1.85$ 不要写成 `1.85000`，$0.0110$ 不要写成 `.011`。
4. **单位进制统一**：全表同一物理量只用一种单位（要么全 s，要么全 ms），
   换算写在表注里（"原始数据为 ms，已换算为 s"）。
5. **空值标注**：缺测写 `—`（不进 `S` 列，用 `\multicolumn{1}{c}{—}` 逃逸）；
   不适用写 `—`；真正为零写 `0.00`。**空着不写最糟**——评委分不清是漏了还是为零。
6. **最优值加粗**：只加粗"答案型"数字（目标值、最优决策量），且**与摘要数字逐位一致**。
7. **显著性标记**：用 `$^{*}$/$^{**}$/$^{***}$` + 表注定义（`* p<0.05, ** p<0.01, *** p<0.001`），
   不要用颜色、不要用背景填充；标记列本身要能被 "删掉它结论会变吗" 检验通过。
8. **表注三件套**：数据来源（E0x）、单位与坐标系、符号/缩写含义。缺一件，评委就得猜。

## 示意图设计规则

1. **唯一的阅读方向**：从左到右（数据流）或从上到下（流程/时序）。
   混用两种方向是示意图第一大乱源。
2. **模块命名用"动词+宾语"**：`遮蔽判定`、`区间合并`、`参数灵敏度分析`；
   不要写 `模块1`、`处理`、`其他`这类无法证伪的名字。
3. **连线有语义，且全篇统一**：

   | 线型 | 语义 | 例子 |
   |---|---|---|
   | 实线箭头 | 数据流 / 主路径 | 输入参数 → 判定器 |
   | 虚线箭头 | 控制流 / 调用 / 可选路径 | 收敛判据 → 提前终止 |
   | 粗线 | 论文主推路线（hero path） | 本文方法 |
   | 无箭头连线 | 并列 / 归属（表示"同一层"） | 三个子问题并列 |

4. **每个连线都要能读成一句话**："A 产生 B"、"A 不满足则回到 B"。读不出来的连线删掉。
5. **配色复用 `PALETTE`**：中性家族画背景/基线，信号家族画本文方法，强调家族画最优/关键点。
   TikZ 里的定义代码见 `references/schematic-and-flowchart.md`。
6. **图内文字能少则少**：方框里放"模块名 + 一句话"，细节进正文；
   一张示意图文字总量控制在 60 字以内（超过说明你在用图写作文）。
7. **图内字号 ≥ 正文的 80%**；`tikzpicture` 里显式写 `font=\small`，
   不要靠 `scale=0.6` 整体缩小（那会把字一起缩小到不可读）。

## 算法伪代码规范

- **必须有输入/输出**（`\Require`/`\Ensure` 中文化为"输入：/输出："），
  且输入输出与正文符号表、附录代码的函数签名一致。
- **必须有行号**（`\begin{algorithmic}[1]`），正文才能写"算法 1 第 7 行"。
- **必须标复杂度或代价**（$O(NK)$、单次迭代耗时、迭代次数上界）。
- **与正文公式编号对应**：伪代码里出现的判据/目标函数，要指向式 (M1)/(4) 的编号，
  不要让评委自己去猜 $\Phi$ 是哪个 $\Phi$。
- **与附录代码一致**：论文里的伪代码与你附录贴的 `.py` 必须是同一套流程
  （变量名可不同，步骤顺序、分支、终止条件必须一致）。
- **不要为了显得高级而贴伪代码**：只有一个闭式解、或三段文字能说清的过程，用公式/文字。

## 工作流

### 第 1 步：立契约
读 P13 `claim_ledger.md` 确认结论编号，读 P11 `experiment_registry.md` 确认数据来源，
为每张计划中的表/图填契约（见上文模板）。**先确认结论，再确认数据，最后才谈排版。**

### 第 2 步：选模式与子型
表格 → `references/three-line-table.md`（含 6 个可直接改用的完整示例：
变量说明表、结果对比表、灵敏度表、参数表、算法对比表、方案明细表）。
示意图 → `references/schematic-and-flowchart.md`（含 3 个可直接编译的 TikZ 模板：
模型框架图、算法流程图、机理示意图）。
伪代码 → `references/algorithm-pseudocode.md`（含 GA/SA/MIP 分支定界/TOPSIS/蒙特卡洛 5 份）。

### 第 3 步：出源码
- 有数据文件的表：用脚本生成，不要手敲数字。
  ```powershell
  python skills\cumcm-table-figure\scripts\table_gen.py --input results\E04\sensitivity.csv `
      --spec results\E04\table_spec.json --out paper\tables\tab_sensitivity.tex
  ```
  `table_gen.py` 会做：自动找每列最优值并加粗、缺失值转 `—`、按定长小数对齐小数点、
  生成表题与表注、并做一次静态自检（列数、三线表合规、进制/位数一致性）。
  没有 spec 时先 `--emit-spec results\E04\table_spec.json` 生成一份草稿再人工核对
  （单位、有效位数、`best` 加粗方向）。
- 示意图：从 `references/schematic-and-flowchart.md` 复制最接近的 TikZ 模板改，
  不要从零画；先定模块和连线，再调坐标。

### 第 4 步：终检
逐条过本文"国赛专属约束"与"设计规则"，再用静态检查脚本兜底：
```powershell
python skills\cumcm-table-figure\scripts\tex_check.py paper\tables\tab_sensitivity.tex
```
检查项：三线表合规（无竖线/无 `\hline`）、`tabular` 列数与每行 `&` 数一致、
花括号与环境配对、表题在表体之前、是否残留 `nan`/`None`/未替换占位符。

> ⚠️ 脚本默认用"定长小数 + 右对齐"（`r` 列），加粗用 `\textbf{}`，任何 TeX 环境都能编译。
> 若改用 `--align decimal`（siunitx 的 `S` 列），加粗会写成 `\bfseries 4.62`：siunitx 通常能保留
> 该字体命令，若你的版本报 `Invalid number`，把那一格改成 `\multicolumn{1}{c}{\bfseries 4.62}` 逃逸，
> 或直接退回默认模式。

### 第 5 步：写入论文
把 `.tex` 用 `\input{paper/tables/tab_sensitivity}` 挂进 `paper/manuscript.tex`，
在表**之前**引用（"灵敏度结果见表 3"），表**之后**补 2～4 句解读文字。
编译后必须**实际打开 PDF 看一眼**：表有没有超出版心、跨页表头是否重复、图内中文是否正常。

## 与 cumcm-figure 的接口

- **分工**：数据点画出来的图 → `cumcm-figure`；表格 + 非数据示意图 → 本 skill。
  一张"框架图 + 结果子图"的组合页，框架部分按本 skill 做，数据面板按 `cumcm-figure` 做。
- **共享口径**：尺寸用 `CM.single_column`（8cm）/`CM.double_column`（16cm）；
  配色用 `PALETTE`（`neutral`/`signal`/`accent`/`compare`）；图内字号下限用正文的 80%。
- **数值一致**：同一数字在摘要、正文、表格、数据图里必须**逐位一致**，
  且都来自 P13 `claim_ledger.md`。表与图同时出现同一结果时，优先保留信息量大的那个。

---

## 什么时候不要用这个 skill

- 折线图、散点图、柱状图、箱线图、热力图、三维曲面、帕累托前沿、龙卷风图、
  收敛曲线、雷达图、网络图 → 用 `cumcm-figure`
- 交互式网页图表（Plotly / Altair / Bokeh）→ 与本 skill 无关
- 纯 EDA 探索阶段的临时统计表（还没有要证明的结论）→ 直接 `pandas.to_markdown()`
- 以 Illustrator / Figma 为主的视觉设计、需要照片级渲染的机理图 → 本 skill 只给 TikZ/Graphviz 路线
- 摘要、正文段落的写作与润色 → 用 `tutorials/process/paper_writing.md`
