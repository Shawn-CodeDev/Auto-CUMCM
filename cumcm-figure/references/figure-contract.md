# 图契约填写指南（figure-contract）

`SKILL.md` 给了契约的字段骨架。本文只回答一个问题：**每个字段填什么才算合格，填错了长什么样。**

契约写在 `sop/project/figure_contract.md`（一图一节），或直接写在回复里。填写时机是 **P11 出结果图、P12 出验证图之前**——
契约没立完就开始写 `plt.subplots`，是本 skill 最严重的误用：你会先得到一个能跑的脚本，然后再也说不清它证明了什么。

> 契约的产物不是文档，是**一条可被反驳的论证链**：C0x ← E0x ← 数据文件 ← 面板 ← 图注。

---

## 0. 十一个字段的合格线（速查）

| 字段 | 合格线 | 不合格的典型样子 |
|---|---|---|
| 图编号 | 与 `experiment_registry.md` 第 4 节「论文图表映射」里的编号**逐字一致** | 写"图 3"，但登记表里图 3 是另一张 |
| 核心结论 | 一句话，带动词、带方向、带数字与单位、有对照对象 | "不同方案的对比" |
| 图像原型 | 从 `SKILL.md` 的 5 个原型里选 **1 个** | 写"综合展示" |
| 面板映射 | 每个面板一个**独有问句**，答不上"盖住它会削弱论证吗"就删 | 每个面板写"展示 XX 结果" |
| 证据层级 | 明确标出 hero 面板、被击败的对照、稳健性面板 | 三个面板都不标，画成等大子图 |
| 数据来源 | E0x + `results/` 下**真实存在**的文件路径 | "来自程序输出" |
| 支撑结论编号 | `claim_ledger.md` 里真实存在、且「可写入论文 = 是」的 C0x | "暂无""待定" |
| 统计要素 | n / 重复次数 / 中心量 / 离散量 / 检验方法五项齐全，或逐项写"不适用 + 理由" | 只写一个"误差棒" |
| 图注草稿 | 遮住正文也能读懂这张图 | "如图 3 所示" |
| 审稿风险 | 一条**具体**的攻击点 + 你手上的证据 | "应该没什么问题" |
| 最终尺寸 | 宽度取 8cm / 16cm / 16cm 之一，并给出高度预算 | "看着办" |

## 1. 逐字段说明

### 1.1 图编号

- **填什么**：`图 <n>`，n 来自 `experiment_registry.md` 第 4 节，不是来自你的临时记忆。
- **合格**：编号在登记表里能查到，且"来源实验编号"列不是"待定"。
- **不合格**：写作时临时插一张图，导致后面图号全部错位——P15 红队把"图表与文字不对应"列为表述分硬伤。
- **操作**：LaTeX 里一律 `\label{fig:...}` + `\ref{}`，禁止手写编号（见 `latex-integration.md`）。

### 1.2 核心结论

一句话。判据与 6 组对照见 §2。

### 1.3 图像原型

从 `SKILL.md` 的 5 个原型里选一个，并写一句"为什么是它"：

| 原型 | 选它的信号 | 常见错配 |
|---|---|---|
| `quantitative-grid` | 结论是"某个数比另一个数大/小" | 用它画机理——机理需要示意，不是网格 |
| `schematic-led` | 不理解系统就看不懂后面的数 | 拿它当结果图，图里没有一个数字 |
| `multi-panel-composite` | 一图看懂全部答案（结果总览） | 把 6 个不相干的图拼在一起 |
| `robustness-panel` | 结论是"参数怎么变结论都不变" | 只扫一个参数就宣称稳健 |
| `spatial-mechanism` | 答案本身是二维/三维场（温度场、定位、遮蔽） | 用三维曲面代替本该用等高线读数的图 |

### 1.4 面板映射

见 §3。

### 1.5 证据层级

见 §5。

### 1.6 数据来源

- **填什么**：`E0x`（来自 P11 登记表）+ 相对路径（如 `results/main/E02/q2_plan.csv`）。
- **合格**：路径在磁盘上存在、字段能对上；路径是相对路径（禁止 `D:\我的文档\...`，否则评审复现时找不到）。
- **不合格**：写"程序算出来的"；写一个跑完就删掉的中间变量名；写 `result.xlsx` 这种无法区分版本的文件名。
- **交付前动作**：把契约里的路径复制到终端 `Test-Path` / `ls` 一遍，全部存在才算过。

### 1.7 支撑结论编号

见 §4。

### 1.8 统计要素

国赛的图注要求写明 n 与误差定义，因此契约里必须先把它们定下来。五项，缺一项就要写"不适用 + 理由"：

| 项 | 微网调度类题的填法 | 仿真/启发式题目的填法 |
|---|---|---|
| n（样本量/单元数） | 144 个时段（10 min/段） | 20 次独立运行 |
| 重复次数 | 确定性求解 1 次；稳健性另做 5 个种子 | 20 次 |
| 中心统计量 | 日均购电成本（元/日） | 20 次的均值/最好值 |
| 离散度量 | 5 个种子间的最大相对漂移 0.4% | 标准差 0.11%，极差 0.21 s |
| 检验方法 | 不适用（确定性优化，无抽样） | Wilcoxon 秩和检验（α=0.05），或"不作检验，仅报离散度" |

**红线**：画了误差棒却在契约里写不出"误差棒代表什么"，就必须删掉误差棒——评委对未定义的误差棒比对没有误差棒更反感。

**统计要素在代码里的落点**：n 与误差定义用 `add_stat_box(ax, "n = 144 时段；误差棒为 5 个随机种子的极差")`
画在轴**上方**（`set_title` 实现，不占绘图区）；关键点的数值用 `annotate_extremum`；
面板标签用 `panel_label`。契约里写不出来的东西，代码里也就画不出来——顺序永远是"契约 → 代码"。

### 1.9 图注草稿

- **合格**：包含量名 + 单位、n、误差定义、方法一句话、面板说明 `(a)...(b)...`。模板见 `figure-caption.md`。
- **不合格**："图 3 不同方案的成本对比。"——没有单位、没有 n、没有方法、没有面板说明。
- **为什么必须在契约阶段写**：图注写不出来，通常不是文字问题，而是**图上缺东西**（缺单位、缺基线、缺 n）。

### 1.10 审稿风险

见 §6。

### 1.11 最终尺寸

- **填什么**：宽度 + 高度，单位 cm。宽度只能取 `CM.single_column`（8cm）/ `CM.double_column`（16cm）/ `CM.one_third`（5cm）三者之一，或按本仓库模板的 `\textwidth = 16cm` 取值。
- **合格**：宽度与 LaTeX 里的 `width=` 完全一致，高度算出正文占用（算法见 `cumcm-layout.md`）。
- **不合格**：设计宽 16cm、插图 `width=\linewidth`（16cm）→ 全图被缩 94%，9pt 字变 8.5pt；或反过来设计 8cm 却在图里写了 6pt 的小字。

## 2. 「核心结论」的写法规则

### 2.1 五要素

一个合格的核心结论必须同时含：

1. **动词**——降低 / 提高 / 收敛到 / 优于 / 主导 / 翻转 / 缩短；
2. **方向**——变高还是变低，提前还是延后；
3. **量**——数字 + 单位，且这个数字来自 C0x；
4. **对照对象**——相对谁（基线 / 现行方案 / 上一问 / 理论下界）；
5. **范围**——在什么条件下成立（可放句尾括号里）。

一条门禁：**把这句话念给队友，他能不能立刻说出"我不同意，因为……"？** 不能，说明这不是结论，是标签。

### 2.2 六组「不合格 → 改后合格」

| # | ✗ 不合格 | 缺什么 | ✓ 改后合格 |
|---|---|---|---|
| 1 | 不同购电方案的对比 | 动词、方向、量、对照全缺 | 引入充放电互斥约束的混合整数模型把全天购电成本降到 38650 元，较线性规划基线低 6.2% |
| 2 | 储能充放电功率随时间的变化 | 只有"是什么"，没有"所以呢" | 储能在谷时段（0.3 元/kWh）以 833 kWh/段充入、在峰时段（1.2 元/kWh）放电，全天恰好完成一次充放循环，未出现同时充放 |
| 3 | 负荷预测结果 | 没有对照基线、没有误差量 | 回归 + 梯度提升树的组合预测把次日负荷 MAPE 从线性基线的 12.4% 降到 8.7%（n=144 段，工作日） |
| 4 | 参数灵敏度分析 | 没有排序、没有量级 | 电价峰谷比是主导敏感参数（±20% 引起成本 ∓17.4%），储能效率次之（±6.4%），寿命损耗系数影响最小（±1.1%） |
| 5 | 算法收敛曲线 | "收敛了"不是结论 | 差分进化在第 262 代把日成本稳定在 38650 元，20 次独立运行的极差 0.21 s（相对 0.4%），小于求解器相对间隙 1.0% |
| 6 | 三维温度场分布 | 空间图最容易只画不说 | 热风入口温度由 60℃ 升至 70℃，使料层中心含水率降至 12% 的时刻由 310 min 提前到 272 min（−12.3%） |

**从这六组里能提炼出的三条改写动作**，遇到写不出的结论时按顺序试：

1. 先问"这两个东西差多少" → 补上差值或相对变化；
2. 再问"跟谁比" → 补上基线或上一问；
3. 最后问"在什么条件下成立" → 补上范围，或者说明这里其实需要一张灵敏度图。

## 3. 「面板映射」的删减判据

### 3.1 唯一判据

对每个面板问一句：

> **把这块盖住，我的论证会变弱吗？**

- 会变弱 → 留下，并把它的独有证据写进契约；
- 不会变弱 → 合并或删除；
- **两个面板删掉后损失一样大 → 它们承载的是同一份证据，合并成一个。**

附带追问（用来抓"看起来有信息、实际没信息"的面板）：

- 这个面板有**只属于它**的坐标轴量名吗？（三个面板共用同一对轴标签，通常意味着三份重复证据）
- 这个面板能读出**一个数字**吗？
- 这个面板存在的原因，是"论证需要"还是"我算了这个量不舍得扔"？

### 3.2 三个真实感的删减案例

**案例 A｜同数据换图形（删饼图）**

- 原契约：`(a)` 各时段购电量构成的堆叠柱；`(c)` 各电源占比饼图。
- 自检：`(c)` 的信息 = `(a)` 的列归一化。盖住 `(c)`，论证完全不受影响。
- 处置：删 `(c)`。腾出的宽度给 `(d)` 龙卷风图，从 5cm 加到 8cm，参数名不再换行。
- 收益：图从 2×2 等大网格变成"1 宽 2 窄"的不等大布局，hero 面板自然浮现。

**案例 B｜子集放大（删放大子图）**

- 原契约：`(b)` 全天 144 段 SOC 轨迹；`(e)` 单独一张"18:00–22:00 峰时段 SOC 放大图"。
- 自检：`(e)` 展示的是 `(b)` 里的一段，是子集不是新证据。
- 处置：删 `(e)`，在 `(b)` 内部用 `ax.inset_axes` 内嵌放大框，或用 `annotate_extremum` 标出"峰时段放电 833 kWh/段"。
- 收益：省下一整个面板的高度，同时把读者的视线留在主曲线上。

**案例 C｜过程图无结论（删流程示意）**

- 原契约：`(d)` "数据清洗流程示意"面板，方框加箭头。
- 自检：它想承载的结论是"我的数据可信"，但图上读不出任何数值；这个结论应由 P5 `data_report.md` 与契约的"数据来源"字段承担。
- 处置：删。若评委确实需要看到清洗前后对比，另做一张 P5 诊断图（`sop/project/figures/data_*.png`）放附录，而不是塞进结果图。
- 判断口诀：**结果图里不放流程图，流程图里不放结果数。**

**反向案例（不该删的）**：`(d)` 稳健性面板看起来"最不重要"，但它是"结论在 ±20% 内不变"的唯一证据，删掉后核心结论从"稳健"退化成"在基准点成立一次"。这类面板可以缩小、可以变灰，但不能删。

## 4. 「支撑结论编号 C0x」怎么取

### 4.1 取法（三步）

1. 打开 `sop/project/claim_ledger.md`，取第 1 节「正式结论台账」的**结论编号列**。
2. 只保留「是否可写入论文 = 是」的行；置信度为「低」的行不作为图的主结论（可进稳健性面板，但图注必须写明"定性"）。
3. 一张图绑 **1 个主结论 + 0～2 个辅结论**。要绑 3 个以上，说明这张图想说的太多——按第 3 节拆图。

### 4.2 取不到时的三条处置路径（按优先级）

| 情况 | 处置 | 禁止做法 |
|---|---|---|
| 图上要表达的其实是某条 C0x 的子集 | 绑 C0x，并把图上措辞的强度**压到不超过账本原文**（账本写"±6.4%"，图上就不能写"约 6%"或"约 6.5%"） | 借 C0x 的名义写一个更强的说法 |
| 图上出现了账本没有的**新数字** | 回 P11 跑一个 ≤30 min 的实验 → 登记 E 编号 → 回 P13 追加 C 编号（这是 P13 允许的唯一追加方式）。来不及 → **删掉这个数字或这个面板** | 直接把数字画上去，等以后补 |
| 图是示意图（框架图 / 机理图 / 算法流程） | 契约里写"绑定 C01–C0k（作为其整体框架）"，并显式声明"不承载独立数值证据"；在 `experiment_registry.md` 第 4 节的"来源实验编号"填"不依赖实验"；导出时传 `save_cumcm_figure(fig, path, allow_empty=True)`——纯示意图没有数据元素，不传这个参数会触发空图告警 | 给示意图硬凑一个 C 编号，让账本看起来更满 |

### 4.3 为什么这条规则值钱

30 页正文的额度是硬的。一张绑不上 C 编号的图，占用的是文字的位置，换来的是一段"看起来做了很多"的错觉。
P13 的账本已经替你把"哪 5～8 条结论值得写进正文"筛过一遍了——**跟着账本出图，等于免费复用了那次筛选。**

## 5. 证据层级：hero / 对照 / 稳健性

| 层级 | 判定问句 | 视觉待遇 | 面积份额 | 契约里怎么写 |
|---|---|---|---|---|
| **主证据（hero）** | 删掉它，核心结论**不成立** | 唯一使用强调色（`PALETTE["accent"]`）；字号 +1；线宽 1.4 | 40–60% | `hero：正面回答核心结论的那一个量` |
| **对照（基线）** | 删掉它，"更优/更低"**失去比较对象** | 中性灰 `PALETTE["neutral"][0]`；细线 1.0–1.2；可只作 hero 面板里的参考线 | 15–30% | `对照：<基线名>（来自 P9 baseline_report）` |
| **稳健性** | 删掉它，结论**仍然成立**，只是不知道有多稳 | 最浅色；虚线；面积最小 | 10–25% | `稳健性：参数/方法/种子的扰动维度` |

三条操作规则：

1. **没有对照就没有"更优"。** P9 的基线报告就是为这个存在的。如果图上只有一条曲线，"提高 6.2%"这句话在图上不可验证。
2. **等大子图是一种误导。** 三个等大面板在视觉上宣称"三份证据同等重要"，而这通常不是事实。用 `GridSpec(width_ratios=...)` 把 hero 做大（代码见 `cumcm-layout.md`）。
3. **稳健性面板可以"安静"，但不能"消失"。** 它变灰、变小是设计，删掉是缺陷。

## 6. 审稿风险自查清单

**填法**：不要写"应该没问题"。从下表里挑出真正适用于本图的 3～5 条，逐条写下你手上的证据。

| 评委的攻击 | 触发条件 | 你必须在契约阶段就准备好的证据 |
|---|---|---|
| "这条曲线只有一条，跟谁比？" | 无基线 | P9 基线方案的数字与来源文件 |
| "误差棒是什么？标准差还是标准误？n 是多少？" | 有误差棒/置信带但图注没定义 | 统计要素五项（§1.8） |
| "纵轴是从 38500 开始的吧？" | y 轴未从 0 起 | 要么从 0 起，要么在轴上画断轴记号并在图注写明"纵轴自 38500 起" |
| "你说的'最优'是全局最优吗？" | 用了 GA/PSO/DE | 20 次独立运行的均值 ± 标准差、极差、与 LP 松弛界的相对间隙 |
| "两条曲线的差距在你的误差范围之内吧？" | 组间差 < 离散度 | 补重复次数，或把结论降级为"趋势一致，差异不显著" |
| "这张图和图 4 说的不是同一件事吗？" | 面板重复 | 按 §3 删并 |
| "这个数据哪来的？" | 无 E 编号 | 绑定的 E0x + `results/` 路径 |
| "你自己清洗过数据吧？" | 有缺失值插值/异常值处理 | 图注一句话说明清洗口径 + 附录给 P5 诊断图 |
| "图上这个数和你表 3 的不一样。" | 有效数字/口径不一致 | 统一到 `claim_ledger.md` 第 5 节的"数字口径统一"表 |
| "峰时段为什么还有紧急购电？" | 结果与物理直觉冲突 | 先自查是否 bug；不是 bug 就写进讨论，别把面板藏起来 |
| "这张图在黑白打印后还能看吗？" | 只靠颜色区分类别 | 加线型/标记/填充纹理（见 `design-theory.md`） |
| "图里的字印出来能看清吗？" | 图内字号 < 8pt | 按最终尺寸反推字号（见 `design-theory.md` 的安全字号表） |

## 7. 完整填好的契约范例（2026 C 题·微网与外部电网电力调控策略）

```text
图编号：            图 3
核心结论：          引入充放电互斥约束的混合整数模型把全天购电成本压到 38650 元
                   （较线性规划基线低 6.2%），且 144 个时段内未触发紧急购电。

图像原型：          multi-panel-composite
                   理由：本图是问题二的"答案总览"，需要同时交付策略本身
                   （怎么看、怎么充放）与它的经济性证据，单一网格装不下。

  (a) 目的：        交付策略本身——全天 144 段功率平衡（负载/光伏/购电/充放电）
```
